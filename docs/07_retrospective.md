# 07. 振り返り

## 得た学び

### API仕様を先に整理する重要性

M5Stack、Web、サーバを並行して作る場合、API仕様が曖昧だと作業の接続時に手戻りが発生します。どのエンドポイントで、どのデータを、どの形式で受け渡すかを早めに整理することが重要だと学びました。

### 並行開発体制の作り方

担当を分けることで開発を進めやすくなる一方、担当間の接続点を誰かが見ていないと仕様のずれが起きます。リーダーとして、進捗確認だけでなく、機能同士のつながりを確認することが必要だと感じました。

### 技術検証のタイミング

UIFlowは初期検証には便利でしたが、開発後半でMicroPythonへ移行することになりました。今後は、早い段階で「最後までその技術で作り切れるか」を検証し、拡張性や保守性も含めて判断したいです。

## 反省点

- API仕様の整理をもっと早く行うべきだった
- 技術選定の検証範囲を初期段階で広げるべきだった
- 公開用資料と学内提出用資料を分けて管理しておくべきだった
- 画面、API、M5Stack側の結合テストの時間をより多く確保すべきだった

## 今後改善したい点

- API仕様書を先に作り、実装中も更新する
- 最小構成で早めにM5Stackとサーバの通信を確認する
- 公開可能なREADMEや設計資料を開発中から整備する
- 入力値チェックやCSRF対策など、Webアプリとしての安全性も改善する
- 手動確認だけでなく、主要なAPIの簡単なテストを追加する

## 面接で説明できるポイント

- スマートフォンを開くこと自体が集中を妨げるという課題設定
- Webで設定し、M5Stackで利用するという役割分担
- UIFlowからMicroPythonへ移行した判断理由
- M5Stack担当・Web担当・サーバ担当が並行開発できるようにAPI仕様を整理したこと
- リーダーとして、進捗確認だけでなく機能間の競合防止を意識したこと
