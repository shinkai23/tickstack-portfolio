## 4. 現在のアイデア
- アイデア 1 (説明、長所、短所):
  - 説明
    - M5Stackを多機能タイマーとして作業中や勉強中にスマートフォンの中でも最低限必要な機能を搭載した「作業サポートデバイス」として活用します。具体的な機能として、1つ目は、現在時刻を常時表示する「時計」としての基本的な機能です。ユーザーは作業中でも常に時間を把握できるため、時間管理をしやすくなります。2つ目は、「ポモドーロタイマー」です。これは25分間の作業時間と15分間の休憩時間を交互に繰り返すタイマー機能で、一定のリズムで作業と休憩を行うことにより、集中力を持続させつつ効率的にタスクを進めることができます。アラーム機能も搭載し、時間になったら音や振動などでユーザーに知らせることができます。最後に3つ目は、ユーザーのToDoリスト（ToDo管理機能）をスマートフォンと連携し、M5Stack上で表示・操作できるようにします。ToDoリストはFlask APIを介して同期され、スマホで登録したタスクがM5Stackにリアルタイムで反映されます。ユーザーは作業の進行状況に応じて、M5Stackのボタン操作によってタスクを「完了済み」として消去することができます。この機能により、スマホに触れることなく作業状況を管理することができます。これらの機能により、作業をするときにスマホを手元から離すことで集中力を高めつつ、作業効率の向上も図ります。これにより、「作業(勉強)の集中をサポートする機能」として特に、学生や受験生、あるいは日々スマホ依存に悩む社会人にとって有効なツールになると考えます。
  - 長所
    - スマホを近くに置かずにするべきことの管理ができる
    - スマホを手元に置かずに、必要な時間管理やタスク確認ができるため、通知やSNSなどによる集中の妨げを防ぐことができる。
    - 寝る前にスマホを触らないことでブルーライトを見ることを軽減することができ、睡眠の質を向上させることができる
    - 用途に特化したシンプルなUIや機能を搭載できるため、不要な機能に惑わされず、目的に集中できる。
  - 短所
    - 緊急時にスマートフォンが手元にないと、すぐに連絡を取ったり通知を確認することができないため、安全面や連絡手段としての課題が残る。
    - 元々の設計にあった「傾けて画面の向きを切り替える」操作がハードウェアやセンサーの制限によって実装困難な場合、代替のUI操作（ボタン操作や時間経過による切り替え）を検討する必要がある。
    - スマホの代替にはなるが、あくまで補助的な機能に限られ、多機能性ではスマホに及ばないため、用途によっては不便を感じることもある。

- アイデア 2 (説明、長所、短所):
  - 説明
    - ToDo管理機能で効率よくタスクを消化できる。
    - 締切や優先度を設定できるため、重要な作業を見逃しにくくなる。
    - タスクの進捗を可視化できることで、達成感を得やすくなる。
  - 長所
    - ToDo管理がしやすくなっている
    - 作業の整理ができるため、時間の使い方が上手くなる。
    - シンプルなUIで直感的に使えるため、誰でもすぐに使い始められる。
  - 短所
    - 機能が充実していないので簡単な管理しかできない
    - カスタマイズ性が低く、利用者の細かいニーズに対応しにくい。
    - 多機能な他アプリと比べると、物足りなさを感じることがある。

## 6. 後半やることと注意点
- 後半の作業:
- 現在未実装の機能を確実に実装し、サービスとしての完成度を高める。
  - 実装を急ぎすぎると設計の見直しが不十分になり、将来的な拡張性に悪影響を与える可能性がある。
- ユーザーが途中で使えない機能に遭遇しないようにすることで、体験の質を向上させる。
  - 機能を隠したりいらない機能を使えなくしたりする対応が不十分だと、ユーザーに誤解やストレスを与える恐れがある。
- 不具合のリスクを減らし、リリース後の信頼性を確保する。
  - バグ修正ばかりに時間をかけすぎると、他の開発作業が滞る
- ToDo管理の効率をもっと上げる。
  - 機能を増やしすぎると操作が複雑になり、逆に使いにくくなる可能性がある
- デバイスの傾きセンサーに依存しないスワイプ操作など、より安定して使える手段を試す。
  - 誤操作を起こしたりすると感度や挙動の調整をしないといけなくなってくるので修正に時間が取られたりする危険性がある。
- 色使いやレイアウトを改善して、見やすく洗練されたデザインを目指す。
  - 特定の色やレイアウトが一部の人にとって見づらくなる可能性がある。
- 使いやすさを重視し、ユーザーが直感的に操作できるUIを実現する。
  - UIを直感的にするつもりでも、ユーザーの期待する操作とずれていると逆に分かりにくくなることがある.
- Flask APIとの通信処理を安定・高速に行えるように調整する。
  - 通信処理の負荷が増えるとバックエンド運用コストが高くなるため、最適化や負荷分散の設計も考える必要がある。
- M5Stackがラグいので処理を軽くするか他の方法を考える
  - 対処法が見つからなければ後々影響力が大きくなっていく
- 把握しているリスク：M5Stackを傾けた時に表示は切り替わる可能性があるが、文字が傾けた方向に傾かない可能性
